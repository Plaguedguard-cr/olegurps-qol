# Учёт патронов и магазинов

AmmoService хранит существующее состояние в Actor flag `world.gurpsAmmoManager`. `ammunitionInventory` содержит отдельные stocks с точным ключом типа/рецепта, физические magazines с собственными ID/ёмкостью/содержимым и installedId. Это один журнал, а числовые magazines/loadedIndex/totalAmmo — его проекция для существующих потребителей.

Операции проходят общую последовательную очередь Actor и проверяют владельца, целые количества, допустимость типа, вместимость и актуальное состояние. Снаряжение переносит патроны из соответствующего свободного запаса, разряжание возвращает тот же тип; переключение установленного магазина не перемещает и не списывает патроны. Удаление магазина безопасно возвращает остаток. Повторный Damage и повторная квитанция атаки не списывают ресурс заново.

Старые неоднозначные/повреждённые данные сохраняются для проверки, не исправляются догадкой. Исторический неподтверждённый тип показывается только при реальных остатках с прежним именем; новое снаряжение запрещено. Нельзя объединять варианты одного калибра. Одноразовая труба/фабричный блок сохраняют отдельный ресурсный контракт, а использованная труба не снаряжается заново.

## Интерфейсы

UT-1 использует тот же журнал и транзакции. Новые каталожные носители сохраняют `sourceFeed`: исходный Shots, ёмкость магазина/трубки, отдельную величину `+1`, время перезаряжания и признак `i`. Количество заряженных патронов учитывается суммарно, включая патронник; тактические операции с отдельным патронником и Ready-время остаются ручными. Например, `5+1(3i)` отображается с двумя ёмкостями и не переименовывается в `6(3)`. Старые магазины не изменяются. UT Shotshell использует девять дробин на физический shell; расход проходит только одну общую квитанцию атаки. Обычные и специальные патроны UT показаны отдельными группами; старые неподтверждённые рецепты — сохранёнными остатками.

Выбор установленного магазина выполняется в прежнем разделе «Патроны» Fire Control. Немодальное ApplicationV2 «Снарядить / Разрядить» оставляет список, содержимое, плавную цветовую полосу, снаряжение/разряжание, создание/удаление. Оно не меняет установленный магазин отдельными кнопками. Оба окна читают одно подтверждённое состояние и реагируют на обновление Actor.

Каждый магазин видимо показывает номер, остаток/ёмкость и полное имя патрона. Строки общего остатка считаются отдельно по каждому ключу типа/рецепта: всего, в магазинах и свободно. Длинное имя переносится в ограниченной прокручиваемой области. Тексты собственного интерфейса русские при Foundry ru и en.

Для подтверждённой замены HT178 без баллистики пустые Damage/Range выделяются красным. Владелец сохраняет значения для точной пары оружие/режим/патрон без изменения исходного каталога. После Save блок свёрнут, красное «Заменяющий» остаётся. Это пользовательские параметры, а не опубликованные числа книги.

## Надёжность и производительность

Окончательный баланс отображается после подтверждения записи. Ошибка/нехватка запаса/недоступный тип не считаются успехом; двойной клик не дублирует операцию. Кеш допускается только для неизменяемых справочных решений, не для количества, прав или approvals. Родительский Actor hook обновляет окно один раз; лишние полные пересчёты исключены.
