9 октября 2026 года. Foundry VTT 14.364, GGA.

## Изменённые файлы

- `scripts/tools/ammo-service.js`: состояние v10, чтение legacy, последовательная очередь операций по Actor, сохранение инвентаря при записи старых снимков, единый расход установленного магазина.

- `scripts/tools/spraying-fire-session-service.js`: общий расход; для нового формата отметка завершённого расхода сохраняется вместе с ресурсами, повторная попытка удаления сессии не списывает их снова.
- `styles/olegurps-qol.css`: компактная разметка, непрерывная шкала заполнения, ограничение высоты содержимого и стабильное место строки статуса.

## Семантика v9 и новый формат

В старом AmmoService `totalAmmo` включает свободные патроны и патроны во всех числовых `magazines`. Свободный запас равен `totalAmmo - sum(magazines)`. `capacity` была общей ёмкостью всех магазинов, `loadedIndex` указывал установленный. При снаряжении и разряжении менялось распределение, а не totalAmmo; выстрел уменьшал установленный магазин и totalAmmo. Старый repair удалял содержимое магазинов при дефиците общего запаса.

Состояние остаётся в `flags.world.gurpsAmmoManager`, версия общего состояния — 10. Внутри каждого оружия:

```json
{
  "ammunitionInventory": {
    "version": 1,
    "stocks": [
      {
        "key": "ht:ammo-item:ht_7_62x39mm",
        "type": {
          "key": "ht:ammo-item:ht_7_62x39mm",
          "source": "catalog",
          "book": "ht",
          "kind": "ammo-item",
          "ammoId": "ht_7_62x39mm",
          "name": "7.62x39mm"
        },
        "rounds": 120
      }
    ],
    "magazines": [
      {
        "id": "persistent-uuid",
        "weaponId": "weapon-id",
        "capacity": 30,
        "rounds": 23,
        "ammoKey": "ht:ammo-item:ht_7_62x39mm"
      }
    ],
    "installedId": "persistent-uuid"
  }
}
```

Свободный запас разделён по типам **внутри конкретного оружия**, сохраняя прежнее владение ресурсами v9. Общего пула патронов между разными записями оружия пока нет. Установка определяется единственным installedId; порядковый номер в интерфейсе не является идентификатором. После удаления номера меняются, UUID других магазинов сохраняются.

Числовые `magazines`, `totalAmmo`, `loadedIndex` и текущая `capacity` остаются производной проекцией для существующих лимитов выстрелов и отчётов. При извлечённом магазине loadedIndex=-1, capacity=0. Сам инвентарь — единственный источник учёта. Сохранение настроек из более старого снимка сохраняет актуальный инвентарь.

## Сохранение legacy

Переход оружия выполняется при первом открытии окна управления. Корректная запись получает отдельные UUID для каждого существующего магазина, прежнее содержимое, ёмкость и установленную позицию. Свободный запас переносится как разница totalAmmo и суммы магазинов. Повторное открытие не повторяет начисление.

Свободный текст ammoType сохраняется без перепривязки к каталогу. Перенесённые патроны получают отдельную идентичность `legacy:<weapon-id>` и подпись о непроверенной совместимости. Они продолжают управляться как прежний запас этого оружия, без выдачи за подтверждённый каталожный патрон. Каталожные flags, собственные overrides, привязки навыков и сторонние настройки сохраняются.

Если totalAmmo меньше суммы магазинов, есть дробные/отрицательные значения, превышение ёмкости или неверный installed index, исходные поля сохраняются в `ammunitionReview.original`. Автоматическое обрезание и repair для такой записи отключены; интерфейс сообщает «Требуется проверка» и блокирует ресурсные операции. Неизвестная версия инвентаря также не переписывается по догадке. Автоматического исправления неоднозначных данных нет.

`ammoUnconfigured=true`, magazines=[], capacity=0, loadedIndex=-1 не создаёт магазин или патроны. Можно явно добавить свободный запас до создания магазинов либо создать пустые магазины без запаса.

## Интерфейс и операции

Окно имеет ширину **490 px**. В живой русской форме с закрытым блоком создания размер был около **490 × 767 px**, одинаковый при 1, 10 и 30 магазинах. При показе объяснения тестового режима высота была около 802 px. Содержимое ограничено высотой экрана и прокручивается. Окно немодальное.

Вверху: оружие, тип патронов, свободный запас выбранного типа, общий запас всех типов и кнопки добавления/удаления свободных патронов. Ниже: один dropdown магазинов, единственная панель выбранного магазина, точные числа, полоса, количество для переноса, снаряжение/разряжение и разряжение целиком, установка/извлечение, удаление. Создание раскрывается компактным блоком ёмкости и количества.

Выбор магазина заменяет только его панель; поля запаса не пересоздаются. При обновлении Actor пересчитывается всё содержимое с сохранением выбранных ID и введённых полей. Одна подписка updateActor удаляется при закрытии.

Массовое создание допускает до 100 магазинов за операцию, до 1000 на оружие, с ёмкостью до 100000. Каждый создаётся отдельным пустым объектом. Пакетное снаряжение отложено.

Снаряжение берёт патроны только из свободного запаса выбранного допустимого типа и проверяет свободные места. Частично заполненный магазин принимает только свой тип. Разряжение возвращает патроны прежнего типа; пустой магазин может принять другой. Добавление и удаление свободного запаса не меняет содержимое магазинов. Установка заменяет прежний установленный магазин без потери патронов; извлечение сохраняет его содержимое.

Удаление магазина автоматически возвращает его содержимое в свободный запас, что явно объясняется рядом с кнопкой. Удаление установленного магазина снимает installedId. Ресурсная операция проверяется на копии актуального состояния и сохраняется одной записью Actor flags; при ошибке проверки или сохранения частичного результата нет.

Полоса имеет ширину `100 * rounds / capacity` и непрерывный hue `120 * rounds / capacity`: красный → жёлтый → зелёный. Есть точные числа и aria-valuenow/aria-valuemax; цвет не влияет на механику.

## Сохранённые остатки удалённого временного патрона

Временный патрон и его GM test mode удалены. Новые запасы такого типа и новое снаряжение недоступны. Существующий ID `olegurps-qol:test-cartridge:v1`, source=`test`, названия, количества, магазины и старые свойства сохранения остаются в исходных данных; миграция и сброс не выполняются. Старое свойство `testEnabled` больше не используется и не создаётся.

В интерфейсах такие неподтверждённые остатки отображаются как «Сохранённый тип (требуется проверка)» / «Saved type (review required)». Они не становятся каталоговыми боеприпасами. Защита AttackProfileResolver, оставляющая их профиль неподтверждённым, сохранена без изменений.

Для безопасного удаления откройте «Снарядить / Разрядить», выберите содержащий остатки магазин и нажмите «Разрядить весь». Можно вместо этого удалить магазин: содержимое вернётся в тот же свободный запас. Затем выберите «Сохранённый тип (требуется проверка)», укажите количество в свободном запасе и нажмите «Убрать». Только это явное действие уменьшает общий боезапас; запись типа с нулевым остатком сохраняется. Обычные LT/HT/UT и их операции не меняются.

## Ограничения

- Свободные запасы принадлежат отдельным записям оружия; перенос между оружием и общий пул Actor требуют отдельного этапа.
- Пакетное снаряжение и смешанные типы внутри одного магазина отсутствуют.
- Неоднозначные legacy записи сохраняются для ручной проверки; автоматического ремонта нет.
- Очередь сериализует операции одного Actor внутри текущего клиента; отдельный серверный арбитраж одновременной правки несколькими клиентами не добавлен.
- Особые правила ракет, одноразовых пусковых установок и комбинированных боевых частей не реализованы заново. При подтверждённых базовых ссылках они используют прежние количественные ограничения; новая схема не добавляет баллистику или специальные HT64-модификаторы.
- Полный набор тестов и визуальная геометрия раскрытого нативного popup не проверялись.

Commit, push, merge и rebase не выполнялись. Посторонние локальные изменения не восстановлены и не удалены.
