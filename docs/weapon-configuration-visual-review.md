# Исправления визуальной проверки Add/Edit weapon

9 октября 2026 года. Foundry VTT 14.364, GURPS Game Aid.

## Изменения этого этапа

- `scripts/tools/weapon-configuration.js`: предварительный список кандидатов, состояние полного поиска, подсчёт результатов, устранение эквивалентных пунктов боеприпасов с сохранением исходной ссылки; вспомогательный редактор больше не управляет Weapon Bond.
- `scripts/tools/weapon-attack-editor.js`: короткая подсказка и tooltip, строка состояния над Catalog match, сохранение текущей модели при поиске; удалены checkbox Weapon Bond и его обработчик.
- `scripts/tools/ammo.js`: редактор получает ранжированных кандидатов существующего WeaponCatalogBindingService вместо Weapon Bond.
- `scripts/tools/weapon-localization.js`, `lang/en.json`, `lang/ru.json`: RU/EN подписи, сообщения и fallback для кэшированной локализации Foundry.
- `styles/olegurps-qol.css`: строка состояния сохраняет место даже при пустом поиске; убраны большие отступы заголовка параметров редактора.
- `tests/weapon-configuration.test.mjs`: 14 новых адресных тестов.
- Этот отчёт и ссылка на него в предыдущем отчёте.

Существующие DialogV2/ApplicationV2, каталожные сервисы, расчёт Weapon Bond и механика боезапаса сохранены. Основное окно остаётся немодальным: `modal: false`, ширина 720 px. Ширина редактора остаётся 520 px. Порядок основной формы: GGA-атака → каталог с карандашом → боеприпас → Governing Skill → Weapon Bond → Save.

## Поиск и состояние

Пустой запрос показывает нейтральный пункт, текущую модель и не более восьми ранжированных кандидатов WeaponCatalogBindingService. Первые сто записей каталога больше не используются как предварительный список. При отсутствии кандидатов остаются текущая модель и нейтральный вариант.

Полный поиск начинается после двух букв или цифр. Он фильтрует весь каталог по названию, доступному калибру, источнику, режиму атаки и обоим ID, без учёта регистра. Знаки `×` и `x` в калибре эквивалентны. Только после фильтрации применяется лимит 100 результатов. Текущая модель закрепляется дополнительно, если не входит в показанные результаты; она не увеличивает счётчик совпадений. Сам поиск не меняет выбранную привязку.

Строка состояния находится между поиском и Catalog match. Примеры из живого каталога:

| Запрос | Состояние EN | Состояние RU |
| --- | --- | --- |
| пустой | пустая строка с сохранением места | пустая строка с сохранением места |
| `A` | Enter at least 2 characters | Введите минимум 2 символа |
| `AK-47` | 1 matches found | Найдено совпадений: 1 |
| `7.62×39` | 6 matches found | Найдено совпадений: 6 |
| `HT` | Showing 100 of 535 matches | Показано 100 из 535 совпадений |
| отсутствующее название | No matches found | Совпадений не найдено |

Placeholder: EN `Name, caliber or ID`, RU `Название, калибр или ID`. Все поддерживаемые поля перечислены в tooltip. Повтора инструкции под списком нет. В живом DOM позиция Catalog match оставалась одинаковой для пустого, короткого, успешного и безрезультатного запроса. Для пустой строки явно задан `display: block`, поскольку стандартное правило Foundry скрывает пустые `.hint` и иначе вызывает сдвиг формы.

## Weapon Bond

Переключатель есть только в основной форме. Редактор не содержит checkbox, подписи, обработчика или возвращаемого редактируемого поля Weapon Bond. Его Save не может перезаписать новое значение основной формы. Хранение остаётся в `weapon.weaponBond`. В живом Fire Control сохранён результат 13 → 14 → 13; канал Weapon Bond даёт 0 → +1 → 0.

## Причина дубля 7.62×39 и сохранность ссылок

Для AK-47 (`equipment_id=eT448e6j7QT5yBB9-`, `weapon_mode_id=W27s4Lm8QlkKVKUPn`) AmmunitionCompatibilityService возвращает две совместимые базовые записи из HT:

| Книга | kind | ammoId | Связь |
| --- | --- | --- | --- |
| ht | ammo-item | ht_7_62x39mm | `ammo_family_id=ht_7_62x39mm` |
| ht | ammo-family | ht_7_62x39mm | единственный `ammo_item_ids=[ht_7_62x39mm]` |

Обе назывались `7.62x39mm`. Раньше интерфейс объединял результаты item/family и выводил одинаковые названия и значения option. Исправление объединяет эту доказанную пару только в представлении. При отсутствии сохранённого выбора приоритет получает конкретная native-запись; при сохранённой привязке к семейству остаётся именно семейство. В Foundry проверено сохранение `kind=ammo-family`, книги и исходного ID после обоих Save.

Аналогичные записи патронов с разными внутренними ID объединяются только при совпадении содержательных данных; совпадения названия недостаточно. Для разных записей одного названия показываются книга, тип записи и достоверно различающаяся характеристика; при недостатке данных добавляется ID. Значения option включают книгу, kind и ID, поэтому одноимённые исходные ссылки различимы.

Семейства с несколькими членами не объединяются с произвольным патроном. В список попадают только уже `compatible` базовые item/family; `undetermined` и специальные HT64-варианты не добавлены. Каталоги и сервисы совместимости не изменялись, патроны и магазины не создавались. Неизменённый старый `ammoType` сохраняется отдельно от визуальной подписи.
