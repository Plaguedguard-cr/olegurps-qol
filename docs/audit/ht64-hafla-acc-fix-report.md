# Buck HAFLA — исправление Acc 0

Стрельба Buck HAFLA исправлена. Подтверждённый WP DM34 можно выбрать, добавить в запас, снарядить и использовать через обычный Fire Control. В Foundry 14.364 / GGA 0.18.23 выполнено настоящее попадание через интерфейс, затем основной и осколочный Damage через штатные диалоги GGA. За атаку списан один заряд; повторные Damage, включая после reload, ничего не списывают.

Ноль не терялся при чтении: в исходном Weapon Reference было `accuracy: null`. Добавлено утверждённое исправление `null` → `"0"` только для режима `Wr3VDL3Z6SR3KCz3K`, HT145. Дополнительно исправлен существующий общий сервис Aim: прежний предел `Acc × 2` обнулял бонусы второй и третьей секунд при известной Acc 0. Для Acc 0 он теперь допускает +1/+2; положительная и неизвестная Acc, порядок остальных бонусов и Move and Attack сохраняют прежнюю обработку.

Новые механики Ready, дальности, дыма и эффектов не создавались. Старые определения автономного оружия, рецепты, магазины и снимки выстрелов автоматически не переписываются. Если ранее сохранённое определение HAFLA содержит `Acc: null`, оно сохраняет это значение: для него можно явно установить Acc 0 в существующем Configure. Новый выбор из исправленного каталога уже получает Acc 0 без ручного ввода.

## Причина и цепочка данных

| Этап | До исправления | После исправления |
| --- | --- | --- |
| Weapon Reference v5.6, HAFLA | `stats.accuracy: null` | `stats.accuracy: "0"` |
| Новый сохранённый профиль оружия | Снимок с неизвестной Acc | Снимок с `"0"` |
| `readStandaloneAttack` | `acc: null`, штатная блокировка готовности | `acc: 0`, блокировки нет |
| Fire Control / завершённый shotSnapshot | UI-сценарий блокирован | `profile.raw.acc: "0"`, `profile.effective.acc: 0` |

`standaloneModeStats` использует `??`, а чтение автономной атаки отдельно проверяет отсутствие значения; эти работающие преобразования не менялись. Неизвестные `null`, `undefined`, пустая строка и нечисловые значения не превращаются в ноль. Проверено адресным тестом, что неизвестная Acc по-прежнему блокирует автономную атаку.

Правило Acc взято из предоставленного пользователем подтверждения HT145; правило дополнительных секунд Aim — B364. Также прочитана фактическая реализация GGA 0.18.23: `module/token-actions.js`, обработчик Aim, использует базовую Acc и последующее увеличение до `Acc + 2`. GGA не изменялся; поправлены две строки предела в уже существующем `fire-service.js`, без нового вычислителя.

## Полный UI-сценарий — PASS

1. Созданы временная копия Actor, unlinked Token и новая каталожная запись Buck HAFLA. Через существующий список выбран именно подтверждённый WP DM34 (`ht_white_phosphorus`), без редактора рецепта.
2. Через окно «Снарядить / Разрядить» добавлены 10 зарядов; создано два контейнера ёмкостью один, в первый помещён один заряд. Установка выполнена в существующем разделе «Патроны».
3. Через кнопку «Огонь» открыт Fire Control. Acc 0 распознана; проверены четыре состояния Aim. Штатная кнопка подтверждения выполнила Hit GGA, результат 7 против 8.
4. Общий запас 10 → 9, установленный контейнер 1 → 0. Завершённый shotSnapshot содержит `spent: 1` и корректную идентичность WP DM34.
5. Кнопка основного Damage открыла штатный диалог `1d-2 burn ex`; GGA создал сообщение с уроном 4. Кнопка осколков открыла `1d(0.2) cut`; сообщение GGA содержит делитель 0.2 и урон 5. Оба сообщения связаны с конкретной атакой, статус `linked`.
6. Переключение на второй пустой контейнер изменило только установленный ID и индекс. Состав запасов и отдельных контейнеров сохранился, общий запас остался 9. Повторный основной Damage использует прежний снимок и формулу, расход 0.
7. После reload Foundry исходное сообщение, shotSnapshot и полное состояние AmmoService совпадают с сохранёнными. Повторный Damage через восстановленную кнопку снова работает; расход 0, снимок не изменён.

Внутренний диагностический API броска не использовался вместо UI. Проверка двух контейнеров не означает возможность перезарядить физически отстрелянную одноразовую трубу: исходный rocket contract не менялся.

Доказательства: [живой сценарий](ht64-hafla-acc-live.json), [очистка и сохранность мира](ht64-hafla-acc-cleanup.json). После удаления только временных объектов остались исходные 12 Actor, 4 пользователя и 6 сообщений. SHA-256 исходных `Actor.system`, Actor/User flags и содержимого/flags старых сообщений совпадают с исходными. Сохранены разрешения боеприпасов, языковая настройка `en` и исходное выделение токенов. Новые строки UI и изменения RU/EN не вводились.

Исторические контрольные суммы не заменены: обратное снятие ровно этой поправки восстанавливает прежний FN-baseline; снятие обеих утверждённых поправок восстанавливает оригинальные HT1.3/HT1.2 хеши. Актуализирован только точный HAFLA-ряд исторического теста +P: известная Acc 0 убирает вторичное препятствие готовности `Acc`; сами запреты +P и все остальные поля/ряды проверяются без изменений. Замороженные отчёты и HT v1.3 не переписывались. Тест WP подтверждает прежнюю revision 1 рецепта, формулы Damage, Range и существующую GM-подсказку. Старые сохранённые данные не мигрировались; живые исходные Actor flags и старые сообщения сохранились.
