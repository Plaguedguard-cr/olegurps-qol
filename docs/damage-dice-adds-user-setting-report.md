# Индивидуальное B269: Modifying Dice + Adds

Дата: 2026-10-18. Версия модуля: **0.2.0**, без изменения.

## Первоисточник и область применения

Проверен оригинальный **GURPS Basic Set: Characters, B269**, блок
*Optional Rule: Modifying Dice + Adds*, в локальной BooksCodex.
В файле `GURPS 4E - Basic Set - Characters.pdf` печатная стр. 269 соответствует
странице PDF 271 (индекс 270). Соответствие установлено по напечатанному номеру,
а не по предположению о смещении. Локальных файлов исправлений для этой книги
не обнаружено. Книга не изменялась и не копировалась в проект.

Правило заменяет накопленные положительные +7 на 2d, затем оставшиеся +4 на 1d.
Бонусы за куб рассчитываются до замены. Примеры:

| Исходно | После B269 |
|---|---|
| 4d+3 | 4d+3 |
| 2d+5 | 3d+1 |
| 4d+4 | 5d |
| 4d+5 | 5d+1 |
| 4d+7 | 6d |
| 4d+8 | 6d+1 |
| 4d+11 | 7d |

В рамках задания правило применяется к основному piercing Damage подтверждённых
режимов HT/UT/LT с `combat_type=ranged`, `weapon_family=firearm`.
Melee, луки, beam, самостоятельные взрывные, осколочные, электрические,
химические и прочие компоненты сохраняют прежние формулы. Неподтверждённая
категория не определяется по названию оружия или одному типу урона.

## Настройка пользователя

В существующее меню настроек **«Навыки оружия»** добавлен checkbox:

**«Преобразовывать прибавки к урону в кубы (B269)»**.

Использован существующий механизм персональных настроек на документе User:
`flags.olegurps-qol.convertDamageAddsToDice`. Отсутствующий флаг означает `true`;
только сохранённое boolean `false` отключает правило. Сохранение идёт через
`game.user.setFlag`, без world settings, localStorage, GM approval или изменения
Actor. Флаг сохраняется между перезагрузками и привязан к userId.

Меню остаётся ApplicationV2 и `restricted:false`. Изменение текущего User
обновляет открытые карточки и Fire Control, включая импортированные и автономные
атаки. Изменение другого User не обновляет расчёт текущего пользователя.
Существующий флажок ТУ сохранён. Новые тексты есть в ru/en и скомпилированном
русском словаре; собственный интерфейс остаётся русским при Foundry ru/en.

## Единый расчёт и история

`damage-dice-adds.js` содержит чистую нормализацию и чтение/сохранение предпочтения.
Общий `AttackProfileResolver` выполняет её последним шагом после:

1. Исходного Damage и выбранного исполнения ETC/LP.
2. Совместимого боеприпаса, опубликованных/пользовательских баллистических данных
   и бонусов за исходные кубы.
3. Существующих источниковых преобразований, включая HT166.

Обновляются `damage.formula`, основной kinetic-компонент,
`damage.effectiveChanges.damage` и `effective.damage`. Поэтому карточка оружия,
Fire Control, подготовленная атака и GGA Damage используют одну формулу.
Нормализация не добавлена в генераторы текста или в повторное открытие Damage.
Множители, бронебойность, minimum и поддерживаемые суффиксы GGA сохраняются.

Пример порядка: LP Boosted Assault Carbine сначала даёт **6d+6**, затем B269
даёт **7d+2**. LP + APDS сначала даёт **6d+12**, затем **9d+1**;
новые кубы не увеличивают бонус APDS. Для ETC + APDS результат до B269
**9d+9**, после — **11d+2**. Самостоятельные боевые части не следуют этому
преобразованию. ETC AMR сохраняет **15d → 6d×4**; функции ETC/LP/HT166 не изменены.

Каждый новый shotSnapshot содержит итоговые формулы и компоненты, а в
`profile.diceAdds` — `version`, `source:B269`, `userId`, `enabled`, `eligible`,
`applied`. Снимок неизменяемый. Повторный Damage читает сохранённый профиль через
существующий damage-shot-link; настройка нажимающего пользователя не читается
для пересчёта формулы. Старые snapshots без `diceAdds` не мигрируются.

Каталоги, GGA/GCS, ресурсные транзакции и формулы ETC/LP/HT166 не редактировались.
Исходные ручные значения оружия не заменяются результатом предпросмотра.
В ChatMessage не добавлены объяснения B269 или общие правила Basic Set;
компактные описания боеприпасов и пользовательские Note сохранены.

## Тесты

Добавлено **25 проверок**: 22 в `damage-dice-adds.test.mjs`, три в существующем
`damage-shot-link.test.mjs`. Покрыты числовые границы и примеры, suffixes,
default=true, два независимых User, сохранение без GM, существующее меню и его
обновления, локализации, HT/UT/LT, исключённые категории, LP Magnum, preview /
Fire Control / prepared profile / snapshot, per-die порядок, APHC/APHEX,
самостоятельные компоненты, неизменность HT166 и ETC AMR, повторные overlay,
Damage с настройкой другого пользователя, старые snapshots и отсутствие
повторного расхода.

В старых тестах обновлены только ожидания итоговых формул, которые теперь
закономерно меняет включённое B269. Проверки исходного APDS-бонуса выполняются
по формуле до B269; исходные LP/ETC и HT166 проверки сохранены. Для базового
боеприпаса после смены магазина ожидается его B269-представление, при этом
исходная Actor.system по-прежнему сравнивается целиком. Тесты не удалялись
и не пропускались; источниковые фикстуры не изменялись.

Адресные прогоны: первоначальные 137 и 184 проверки выявили старые ожидания и
ошибки подготовки новых фикстур; последующие 242 проверки локализовали оставшиеся
ожидания. Финальные 22 адресные проверки также прошли, включая реальные
каталожные режимы HT/UT/LT и независимый piercing follow-up.
После исправлений выполнен полный финальный набор:

`node --test tests/*.test.mjs`

**89 файлов; 2149 PASS; 0 FAIL; 0 SKIP; 0 CANCELLED; 0 TODO.**
Продолжительность 26.63 с. TAP: `%TEMP%\olegurps-b269-full-final.tap`.
Этот прогон выполнен после последней правки кода и тестов.
Синтаксис изменённых JS/MJS, строгий UTF-8, локализации и `git diff --check` прошли.

## Живая проверка Foundry

Foundry **14.364**, GGA **0.18.23**, модуль **0.2.0**, язык Foundry `en`.
После паузы локальная сессия была возобновлена. Созданы отдельные временные
Actor/Token и два временных User с ролью **Player**, без GM-прав, с владением
только тестовым Actor. Пользователи вошли в разные изолированные браузерные
контексты, сохранили флажки через настоящее меню и перезагрузили Foundry.

| User | Сохранённый флаг | После reload | Результат |
|---|---:|---:|---|
| `555GgnC6vdjyz7Ln` | false | false | Личный Damage 4d+5 |
| `TePDO2Ap6YVWrH0a` | true | true | B269 остаётся включённым |
| Исходный GM | отсутствует | отсутствует | default=true, карточка 5d+1 |

Выбор первого игрока не изменил второй User или настройки исходного GM.
На одном Actor одновременно подтверждены разные карточки: у первого игрока
**4d+5**, у GM с отсутствующим флагом **5d+1**. Русская подпись checkbox реально
загрузилась при английском языке Foundry; исходный язык не менялся.

Игрок без GM выполнил LP Magnum Boosted с отсутствующим флагом:
карточка и Fire Control показывают **5d+1 pi++**, в shotSnapshot записаны эта
формула и `enabled:true` с userId стрелявшего. Патроны **12 → 11**,
топливо в четвертях **156 → 150**.

После выключения B269 и reload тот же игрок нажал настоящую ссылку Damage
старого сообщения. В native Roll Confirmation остались **5d+1 pi++**;
настоящий GGA Damage содержит **`5d6[Damage] + 1 + 0`**, один термин с пятью d6.
Формула физического броска изменена, это не только подпись.

Новая атака с выключенным правилом сохранила **4d+5 pi++**, `enabled:false`:
патроны **11 → 10**, топливо **150 → 144**. Второй игрок с включённым B269
нажал Damage этой атаки дважды. Оба native броска сохранили
**`4d6[Damage] + 5 + 0`**, четыре d6; оба связаны с исходным attackId.
Его личная настройка не пересчитала чужую прошлую атаку.

Полное сравнение состояния и обоих snapshots до/после повторного Damage
подтвердило неизменность патронов, топлива, receipts и истории. Состояние и
первый snapshot также точно совпали после reload. Оба основных сообщения
попадания сохраняют native 3d6 и Damage; приватные расчёты сохранены,
описание боеприпаса остаётся компактным.

### Очистка

Удалены временные Actor, Token, два User, семь сообщений проверки
(два попадания, две карточки расчёта, три Damage), а также восемь приветственных
сообщений GGA/Dice So Nice, созданных входом в новые тестовые сессии.
Временные браузерные контексты и тестовые hooks закрыты.

После очистки **весь начальный снимок совпал точно**: 12 исходных Actor,
Token сцены, 17 исходных ChatMessage, четыре исходных User, выделение Token,
targets, язык и rollMode. Ни один исходный snapshot не переписан.
